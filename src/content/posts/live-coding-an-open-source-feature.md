<p class="has-medium-font-size">How do I approach a new feature in an open source project? How do I TDD a frontend feature? What do we use for cross-browser testing? All this and more in this live coding session recording</p>



<p>This is the recording of the first live session.</p>



<p>I developed a feature taken from the issues list on <a href="https://github.com/vonage/vivid-3" data-type="URL" data-id="https://github.com/vonage/vivid-3" target="_blank" rel="noreferrer noopener">Vivid</a> &#8211; an open-source web-components based UI library. </p>



<p>After around an hour of live coding, <a href="https://twitter.com/StefanAtDev" target="_blank" data-type="URL" data-id="https://twitter.com/StefanAtDev" rel="noreferrer noopener">Stefan</a> and <a href="https://twitter.com/TallyBarak" target="_blank" data-type="URL" data-id="https://twitter.com/TallyBarak" rel="noreferrer noopener">Tally</a> joined in to add their experience regarding Jest and Playwright. </p>



<p>Stefan mentioned one can use the Jest <code><a href="https://jestjs.io/docs/api#testeachtablename-fn-timeout" data-type="URL" data-id="https://jestjs.io/docs/api#testeachtablename-fn-timeout" target="_blank" rel="noreferrer noopener">each</a></code> functionality to arrange the tests in a clearer and cleaner manner. He also pointed out some good points regarding the usage of spies.</p>



<p>Tally, who is a Playwright expert, mentioned Playwright&#8217;s out-of-the-box support for Shadow DOM as opposed to Cypress&#8217; somewhat lacking support in that regard.</p>



<p>Eventually, we looked at Vivid&#8217;s in-house visual regression tests mechanism and discussed multiple challenges in cross-browser testing.</p>
